# 合成阵列近似与信道冲激响应数据维度说明

## 1. 文档目的

本文说明阵列路径求解方式对信道冲激响应、传播时延、到达角、离开角和路径有效性数据维度的影响，并给出当前雷达仿真平台中的文件组织、维度解释、存储量估算、波束形成关系和故障判断方法。

本文适用于当前项目采用的射线追踪计算库版本：

```text
sionna-rt==2.0.1
```

配置项为：

```yaml
path_solver:
  synthetic_array: true
```

或者：

```yaml
path_solver:
  synthetic_array: false
```

## 2. 核心结论

关闭合成阵列近似后，最明显的变化不是复信道系数一定增加维数，而是传播时延、路径角度、路径有效性和交互信息从“设备对共享一套路径”变为“每个收发阵元对分别具有路径信息”。

复信道系数数组在两种方式下通常都保留接收阵元维和发送阵元维：

```text
[接收设备, 接收阵元, 发送设备, 发送阵元, 路径槽, 时间采样点]
```

传播时延数组则存在关键差别：

```text
合成阵列近似：
[接收设备, 发送设备, 路径槽]

逐阵元物理求解：
[接收设备, 接收阵元, 发送设备, 发送阵元, 路径槽]
```

因此，不能用传播时延数组的元素总数表示路径数量。路径槽数应从复信道系数数组的倒数第二维读取。

## 3. 两种阵列求解方式的物理含义

### 3.1 合成阵列近似

合成阵列近似首先在发送设备和接收设备的相位中心之间求解传播路径。一个设备对只保存一套几何路径，包括反射、绕射、透射和漫反射等传播过程。

随后，计算库依据路径的离开方向、到达方向、阵元位置和阵元方向图，推导不同阵元上的复数幅度和相位。因此，复信道系数仍然可以具有完整的收发阵元维，但同一设备对内的阵元共享几何路径和传播时延。

该方法的主要特点为：

- 路径搜索次数少；
- 传播时延和路径角度数据量小；
- 适合阵列孔径相对传播距离较小的情况；
- 适合界面调试、参数扫描和大规模场景初步计算；
- 阵元之间的遮挡差异和近场几何差异由近似处理，不能完整反映。

### 3.2 逐阵元物理求解

关闭合成阵列近似后，射线追踪器按照每个发送阵元与每个接收阵元的实际位置建立传播链路。不同阵元对可以具有不同的传播时延、路径角度、遮挡状态、交互物体和有效路径集合。

该方法的主要特点为：

- 阵元位置直接进入路径几何计算；
- 能反映较大阵列孔径引起的时延差和角度差；
- 能反映局部遮挡导致的阵元可见性差异；
- 更适合近场传播、大孔径阵列和精细波束形成研究；
- 计算量、显存占用和路径元数据体积明显增加。

逐阵元物理求解仍然属于确定性传播建模，不自动包含以下硬件效应：

- 阵元互耦；
- 射频通道幅相误差；
- 本振相位噪声；
- 模数转换量化误差；
- 热噪声和接收机噪声系数；
- 阵列安装误差和校准残差。

如果研究目标包含这些效应，需要在传播求解之后增加独立的阵列和接收机误差模型。

## 4. 维度符号定义

阵列局部坐标、设备中心、收发基线和阵元编号的完整定义参见 [雷达阵列坐标、朝向与阵元编号说明](RADAR_ARRAY_COORDINATE_AND_INDEXING.md)。

为避免把设备、阵元和路径槽混为一体，本文使用以下符号：

| 符号 | 含义 |
|---|---|
| $N_{r}$ | 接收设备数量 |
| $M_{r}$ | 每个接收设备的阵元数量 |
| $N_{t}$ | 发送设备数量 |
| $M_{t}$ | 每个发送设备的阵元数量 |
| $P$ | 路径槽数量 |
| $L$ | 信道时间采样点数量 |

对于规则平面阵列：

$$
M_{r}=M_{r,\mathrm{行}}M_{r,\mathrm{列}}
$$

$$
M_{t}=M_{t,\mathrm{行}}M_{t,\mathrm{列}}
$$

例如，十六行十六列接收阵列具有：

$$
M_{r}=16\times16=256
$$

## 5. 复信道系数的维度

文件 `cir.npz` 中的 `a` 表示基带等效复信道系数，其维度为：

$$
\mathbf{a}\in
\mathbb{C}^{N_r\times M_r\times N_t\times M_t\times P\times L}
$$

对应数组顺序为：

```text
[接收设备, 接收阵元, 发送设备, 发送阵元, 路径槽, 时间采样点]
```

第六维保存信道随时间变化的采样。当前项目默认只计算一个时间采样点，因此最后一维通常为一。若后续增加多时刻多普勒演化，该维会大于一。

需要注意：合成阵列近似并不意味着 `a` 会删除阵元维。近似发生在路径几何求解阶段，而阵元方向图、阵元位置产生的相位差仍会作用于复信道系数。

## 6. 传播时延的维度

文件 `cir.npz` 中的 `tau_s` 表示传播时延，单位为秒。

### 6.1 合成阵列近似开启

所有阵元共享设备相位中心求得的传播路径：

$$
\boldsymbol{\tau}\in
\mathbb{R}^{N_r\times N_t\times P}
$$

对应数组顺序为：

```text
[接收设备, 发送设备, 路径槽]
```

### 6.2 合成阵列近似关闭

每个收发阵元对具有独立时延：

$$
\boldsymbol{\tau}\in
\mathbb{R}^{N_r\times M_r\times N_t\times M_t\times P}
$$

对应数组顺序为：

```text
[接收设备, 接收阵元, 发送设备, 发送阵元, 路径槽]
```

到达天顶角、到达方位角、离开天顶角、离开方位角和路径有效性通常遵循与传播时延相同的链路维度。

## 7. 具体算例

假设系统具有：

- 一个接收设备；
- 十六行十六列接收阵列，共二百五十六个接收阵元；
- 一个发送设备；
- 一个有效发送孔径；
- 四千七百一十个路径槽；
- 一个时间采样点。

则复信道系数形状为：

```text
(1, 256, 1, 1, 4710, 1)
```

逐维含义为：

| 维序号 | 长度 | 含义 |
|---|---:|---|
| 第一维 | 1 | 接收设备 |
| 第二维 | 256 | 接收阵元 |
| 第三维 | 1 | 发送设备 |
| 第四维 | 1 | 发送阵元或预合成发送孔径 |
| 第五维 | 4710 | 路径槽 |
| 第六维 | 1 | 时间采样点 |

关闭合成阵列近似后，传播时延形状为：

```text
(1, 256, 1, 1, 4710)
```

传播时延数组的元素总数为：

$$
1\times256\times1\times1\times4710=1\,205\,760
$$

但是，路径槽数量仍然只有：

$$
P=4710
$$

数值 $1\,205\,760$ 表示“阵元链路数量乘以路径槽数量”，不能解释为独立路径数量。

如果开启合成阵列近似，并假设路径槽数量恰好仍为四千七百一十，则传播时延形状为：

```text
(1, 1, 4710)
```

实际计算中，两种求解方式得到的路径槽数不保证相同，因为逐阵元物理求解可能发现不同的遮挡关系和传播路径。

## 8. 发送孔径预合成对维度的影响

当前平台支持把自定义发送孔径权重直接嵌入发送方向图。此时，多个物理发送阵元的相干作用已经在方向图计算阶段完成，信道文件中的发送阵元维可能仍为一。

因此，界面中配置了多行多列发送阵列，并不必然意味着 `a` 的第四维等于发送阵元总数。判断时应区分：

- 发送孔径是否已经嵌入物理方向图；
- 是否保留独立发送阵元通道；
- 后处理阶段是否还需要执行发送端相干合成。

如果保留六十四个独立发送阵元，同时使用二百五十六个接收阵元，则复信道系数理论形状为：

```text
(1, 256, 1, 64, P, L)
```

这种配置的数据量远大于发送孔径预合成方式。

## 9. 路径槽与有效路径

路径槽是计算库用于对齐不同链路结果的存储位置，不等于每个槽都包含有效传播路径。

有效路径应由以下条件共同确定：

- 有效性标记为真；
- 传播时延为有限数值；
- 传播时延大于系统设置的最小时延；
- 对应复信道系数不存在无效数值。

因此，应区分三个数量：

| 数量 | 定义 |
|---|---|
| 路径槽数 | 复信道系数数组倒数第二维的长度 |
| 阵元链路路径记录数 | 所有阵元链路上的路径槽总数 |
| 有效传播路径数 | 通过有效性和时延条件筛选后的记录数 |

当前平台统一使用复信道系数数组的倒数第二维确定路径槽数：

```text
路径槽数 = a.shape[-2]
```

这可以避免把阵元维误乘到路径数量中。

## 10. 项目输出文件

### 10.1 原始信道文件

文件：

```text
cir.npz
```

主要内容：

| 名称 | 含义 |
|---|---|
| `a` | 基带等效复信道系数 |
| `tau_s` | 传播时延，单位为秒 |

该文件保留原始阵元维，不会为了界面展示而折叠。

### 10.2 逐阵元路径文件

文件：

```text
paths_per_element.npz
```

该文件仅在逐阵元路径元数据需要折叠时生成，保存内容包括：

- 逐阵元传播时延；
- 路径有效性；
- 到达角和离开角；
- 多普勒频移；
- 交互类型；
- 交互物体编号；
- 路径顶点。

该文件用于精细阵元级分析和问题追踪。

### 10.3 逐路径摘要文件

文件：

```text
paths_summary.npz
```

为了兼容路径统计、波束形成、调频连续波处理和界面缓存，平台会为每个路径槽选取一条有效阵元链路作为代表记录，生成统一的逐路径摘要：

```text
(1, 1, P)
```

该过程不是对所有阵元时延进行算术平均。原始逐阵元信息仍保存在 `paths_per_element.npz` 中。

## 11. 与接收波束形成的关系

对于第 $p$ 个路径槽，将收发阵元之间的复信道系数写为矩阵：

$$
\mathbf{A}_{p}\in\mathbb{C}^{M_r\times M_t}
$$

发送权重为 $\mathbf{w}_{t}$，接收权重为 $\mathbf{w}_{r}$，则相干合成后的路径系数为：

$$
h_{p}=\mathbf{w}_{r}^{\mathrm{H}}\mathbf{A}_{p}\mathbf{w}_{t}
$$

其中，上标 $\mathrm{H}$ 表示共轭转置。对应路径功率为：

$$
P_{p}=|h_{p}|^{2}
$$

关闭合成阵列近似后，$\mathbf{A}_{p}$ 和传播时延包含更完整的阵元级几何差异，因此相干合成能够利用更真实的阵元相位关系。代价是需要处理更大的路径元数据和更高的射线追踪计算量。

## 12. 存储量估算

以形状 `(1, 256, 1, 1, 4710, 1)` 为例，假设复信道系数使用单精度复数，每个元素占八字节，则未压缩的 `a` 约占：

$$
1\times256\times1\times1\times4710\times1\times8
=9\,646\,080\ \text{字节}
$$

约为九点二兆二进制字节。

若传播时延使用单精度实数，每个元素占四字节：

合成阵列近似下约为：

$$
1\times1\times4710\times4=18\,840\ \text{字节}
$$

逐阵元物理求解下约为：

$$
1\times256\times1\times1\times4710\times4
=4\,823\,040\ \text{字节}
$$

这还没有计入有效性、角度、交互、物体编号和路径顶点。实际文件采用压缩存储，磁盘占用与数值重复程度有关；运行时内存和显存仍应按未压缩数组估算。

## 13. 数据读取与维度检查

可使用以下程序查看结果文件中的名称、形状和数据类型：

```python
from pathlib import Path

import numpy as np

run_dir = Path("需要检查的结果目录")

for file_name in ("cir.npz", "paths_summary.npz", "paths_per_element.npz"):
    file_path = run_dir / file_name
    if not file_path.exists():
        continue
    print(file_name)
    with np.load(file_path, allow_pickle=False) as archive:
        for name in archive.files:
            value = archive[name]
            print(f"  {name}: 形状={value.shape}, 类型={value.dtype}")
```

判断路径槽数：

```python
with np.load(run_dir / "cir.npz", allow_pickle=False) as archive:
    path_slot_count = int(archive["a"].shape[-2])
```

不要使用以下方式判断路径数量：

```python
path_count = archive["tau_s"].size
```

因为关闭合成阵列近似后，该数值包含收发阵元维。

## 14. 求解方式选择建议

### 14.1 优先使用合成阵列近似的情况

- 进行界面和流程调试；
- 扫描大量雷达位置；
- 阵列孔径远小于传播距离；
- 主要关注场景级覆盖和粗粒度路径统计；
- 显存和计算时间受限。

### 14.2 优先使用逐阵元物理求解的情况

- 研究大孔径阵列；
- 研究近场传播；
- 分析阵元局部遮挡；
- 验证高分辨率接收波束形成；
- 需要逐阵元时延、角度和路径交互信息；
- 研究结果对阵元级相位一致性敏感。

建议先使用小阵列、较低射线采样量和较小最大传播深度完成逐阵元试算，再逐步增加阵元数和射线数量。直接使用大阵列和高路径上限容易造成显存和磁盘占用快速增长。

## 15. 常见误判与故障定位

### 15.1 把传播时延元素总数当成路径数

错误判断：

```text
路径数 = tau_s.size
```

正确判断：

```text
路径槽数 = a.shape[-2]
```

### 15.2 把路径槽数当成有效路径数

路径槽中可能包含无效填充项。有效路径数必须结合有效性标记和传播时延条件计算。

### 15.3 认为关闭近似后复信道系数一定增加维数

复信道系数原本就可能包含收发阵元维。关闭近似后最稳定、最明确的变化是传播时延和路径元数据增加阵元维，而路径槽数量和具体数组长度取决于场景与阵列配置。

### 15.4 认为关闭近似等于完整电磁阵列仿真

逐阵元路径求解提高了传播几何精度，但不自动模拟阵元互耦、端口阻抗、馈电网络、射频通道误差和接收机噪声。

### 15.5 错误报告应包含的信息

发生维度错误时，至少应提供：

- `a` 的形状和数据类型；
- `tau_s` 的形状和数据类型；
- `valid` 的形状；
- 发送与接收阵列行列数；
- 合成阵列近似配置值；
- 路径求解最大深度和射线采样量；
- 完整错误堆栈；
- 任务编号和结果目录。

项目提供错误报告收集脚本：

```bash
./scripts/collect_error_report.sh --job-id 任务编号
```

## 16. 本项目的兼容处理

当前平台执行以下兼容处理：

1. 从 `a` 的倒数第二维读取路径槽数；
2. 保留 `cir.npz` 中的原始复信道系数和传播时延；
3. 将完整逐阵元路径元数据保存为 `paths_per_element.npz`；
4. 生成统一逐路径摘要供后续处理使用；
5. 自动识别旧版逐阵元路径文件并完成无损迁移；
6. 波束形成前检查路径轴、接收阵元轴和发送阵元轴；
7. 单个损坏结果不会阻止后续新任务运行。

相关实现位置：

- `experiments/sionna_radar/src/sionna_radar/processing.py`：路径槽识别和逐阵元元数据规范化；
- `experiments/sionna_radar/src/sionna_radar/runner.py`：阵列求解配置和原始结果保存；
- `services/radar_api/app/core/path_layout.py`：旧结果自动兼容；
- `services/radar_api/app/core/beamforming.py`：信道维度识别和相干合成。

## 17. 总结

关闭合成阵列近似后：

- 每个收发阵元对具有独立的传播时延和路径元数据；
- 复信道系数继续保留接收阵元、发送阵元、路径槽和时间采样维；
- 路径槽数必须从复信道系数数组倒数第二维读取；
- 传播时延元素总数不能解释为路径数量；
- 波束形成可以利用更完整的阵元级相位和几何差异；
- 计算量、显存、内存和结果文件体积都会增加；
- 传播几何精度提高不代表已经包含完整的阵列电磁和射频硬件误差模型。
