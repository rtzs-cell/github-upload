## 0. 如何阅读本教程

- **第一次使用**：依次阅读第 1、2、5、8、9 节，先完成一个低复杂度单测点实验。
- **分析已有结果**：依次阅读第 4、5、12、13、14 节，再按第 8 节做收敛和物理一致性检查。
- **迁移到其他机器**：先阅读第 17 节，再按独立的《打包与迁移部署指南》操作。
- **需要公式和术语**：阅读第 10 至 14 节，并配合 `RADAR_GLOSSARY.md`。

## 1. 数据之间的关系

- **实验方案**：一组可继续编辑的场景和雷达参数，不包含仿真结果。
- **仿真任务**：一次提交。单测点任务包含一个子任务，批量任务可包含多个相互独立的测点子任务。
- **仿真结果**：一个已经完成的测点结果。每条记录都有独立 CIR、路径、MPC、FMCW 和下载文件。
- **内置示例结果**：可选的只读对照数据，不属于用户历史记录。

删除方案不会删除由它产生的结果；删除仿真结果也不会删除其来源方案。

## 2. 建立第一次实验

1. 打开 `http://127.0.0.1:8000`；前端开发模式使用 `http://127.0.0.1:5173`。
2. 进入“实验方案”，选择空白场景、双建筑或街谷作为起点，然后点击“新建实验方案”。
3. 打开右侧“场景几何”，新增建筑并设置名称、中心坐标、长宽高和材质，保存场景。
4. 在“雷达参数”设置雷达中心位置和观察点。主视轴为“雷达中心 → 观察点”的单位方向。
5. 设置载频、FMCW 带宽、chirp 时长、chirp 数和 ADC 采样数。
6. 设置发射阵列和接收阵列的行列数与导向角，检查方向图预览。
7. 初次验证建议关闭漫反射、最大反射阶数设为 1，并使用较少射线。
8. 点击“运行雷达仿真”。

## 3. 批量测点与逐项结果

API 的 `mode="campaign"` 可提交多个 `poses`。每个 pose 是独立子任务：

```json
{
  "mode": "campaign",
  "poses": [
    {"center_m": [0, 0, 10], "look_at_m": [450, 0, 40]},
    {"center_m": [0, 10, 10], "look_at_m": [450, 10, 40]}
  ]
}
```

一个子任务完成后会立即：

1. 写入该测点的运行目录；
2. 更新 `runs_index.csv`；
3. 出现在“我的仿真结果”；
4. 开放该测点的单文件下载和结果包下载。

不需要等待整批完成。后续测点失败时，之前已完成的测点仍然保留。

## 4. MPC 结果

MPC 页采用 AoA 等距柱状全景定义。

路径权重：

```text
A_l = |a_l|
```

角度到像素：

```text
x_l = (180 deg - phi_l) * 3
y_l = theta_l * 3
```

其中 `phi` 是 AoA 方位角，`theta` 是 AoA 天顶角。默认使用 8×8、间距 0.5λ 的矩形孔径主瓣宽度核：

```text
HPBW ~= 0.886 / (N*d)
sigma = HPBW / 2.3548
```

可下载文件：

- `mpc_panorama.npz`：未归一化 dB 数组、归一化数组和角度坐标；
- `mpc_panorama.png`：360°×180° 全景图；
- `mpc_view_front/right/back/left.png`：四个 90° 透视视角；
- `analysis_gate_mpc.csv`：分析范围内的逐路径表，它是补充路径数据，不是 MPC 全景图。

跨测点做机器学习比较时，应使用统一的全局归一化边界。单帧 PNG 适合查看结构，不适合直接比较绝对强弱。

## 5. 结果阅读顺序

1. **概览**：确认路径数、主峰距离和射线采样参数。
2. **MPC**：查看全景角度能量结构和四方向裁切。
3. **传播路径**：选中强路径，检查完整 Tx → 交互点 → Rx 折线。
4. **雷达回波**：检查距离-多普勒图、距离/速度分辨率和 CFAR 检测。
5. **波束成形**：确认阵列响应峰值与设置的导向角一致。

## 6. 分项下载

结果页底部提供：

- 分析结果包；
- 完整结果包；
- MPC 原始数组和每张图；
- CIR、原始路径数组、逐路径 CSV；
- 波束形成和 FMCW 数组。

需要重新做阵列相干合成时才下载大型 `cir.npz`。只训练 MPC 图像时，下载 MPC 数组或四张视图即可。

## 7. 删除记录

- 默认打开“我的仿真结果（可删除）”。
- 点击记录右侧垃圾桶按钮并确认，可删除该结果及缓存、下载包和路径导出。
- 方案有独立删除按钮；删除方案不影响结果。
- 正在运行的任务受到保护。
- 内置示例结果标记为只读，不会显示删除按钮。

## 8. 验证建议

1. 用已知距离的单反射面检查 `R=c*tau/2`。
2. 增加射线数，检查主峰位置与总功率是否收敛。
3. 更换随机种子，确认结论不是单次随机采样造成。
4. 分别开启镜面反射和漫反射，比较 MPC 角度结构变化。
5. 定量分析使用 NPZ 数组，PNG 仅作为显示结果。

## 9. 界面功能地图

### 9.1 左侧工作区

| 页面 | 内容 | 是否可编辑 |
|---|---|---|
| 实验方案 | 场景和雷达参数模板 | 是 |
| 我的仿真结果 | 工作台生成的已完成测点 | 否；修改参数后生成新记录 |
| 内置示例结果 | 可选的只读对照数据 | 否 |
| 术语教程 | 原理、公式、参数解释和操作教程 | 不适用 |

本地方案和本地结果分别保存。选中历史结果后，右侧显示的是该次仿真的参数快照，不会自动恢复成可覆盖原记录的状态。

### 9.2 中央工作区

- 三维场景：显示建筑、雷达主视轴、当前选中的完整传播路径和交互点；
- 概览：显示路径总数、主峰距离、分析范围内能量和统计图；
- MPC：显示 AoA 全景、四张透视图以及补充路径分析；
- 雷达回波：显示距离-Doppler、分辨率、路径覆盖率和 CFAR；
- 波束形成：显示发射方向图、接收数字波束响应和合成后的强路径；
- 距离角谱：显示距离-方位与距离-俯仰功率直方图；
- 结果下载：提供结果包和单文件下载。

### 9.3 右侧检查器

“雷达参数”用于编辑方案或查看结果快照；“场景几何”用于编辑方案中的建筑和材质；“路径与对象”用于筛选并选择单条路径。结果快照不可原地修改，避免参数和归档数据不一致。

桌面端可以拖动左右栏边界调整检查器宽度，也可以拖动三维场景下方的短横线调整视图高度。尺寸保存在当前浏览器中；窄屏设备自动改为纵向布局。

## 10. 场景与雷达几何参数

### 10.1 场景预设与几何编辑

场景预设只提供可编辑的初始几何，不代表固定仿真方案。空白场景仅含地面；双建筑和街谷用于快速建立常见布局。建筑名称是面向用户的显示名称，内部对象标识保持稳定，两者互不替代。

每次点击“保存场景”都会在实验目录的 `scene/revisions/` 下生成新的 XML 和网格文件，并让当前方案指向新修订。已经完成的仿真结果继续引用提交时的旧修订，因此修改方案不会暗中改变历史结果。

在三维场景中点击建筑后，建筑会高亮，右侧自动定位到对应几何项。场景工具栏提供：

- “移动”：拖动红、绿、蓝坐标轴调整建筑中心，位置按 0.5 m 吸附；
- “缩放”：拖动轴端控制点调整长、宽、高，比例按 0.05 吸附；
- “适应场景”：建筑移动到当前视野外时，主动重新计算相机取景范围；
- 撤销与重做：逐步恢复三维拖动或数值输入；
- “恢复已保存”：丢弃当前所有未保存的场景修改。

三维操作和右侧数值输入使用同一份临时配置。建筑高度最小为 0.1 m，提交三维变换时会保证建筑底面不低于地面。只有点击“保存场景”后才会生成新的场景修订。

建筑编辑提交后不会自动改变相机位置或观察目标。只有切换方案、聚焦传播路径或点击“适应场景”才会重新设置视角。

方案和本地仿真结果均可通过列表中的铅笔按钮修改显示名称。改名不会改变实验编号、运行编号或文件目录；只读示例结果不能改名。

### 10.2 雷达位置和主视轴

雷达中心为 $\mathbf p_r$，观察点为 $\mathbf p_t$。主视轴单位向量为：

$$
\mathbf b=\frac{\mathbf p_t-\mathbf p_r}{\|\mathbf p_t-\mathbf p_r\|_2}.
$$

观察点只用于定义朝向，不表示该位置一定存在目标。界面中的发射阵列和接收阵列导向角是相对主视轴的偏移。

### 10.3 方位角、仰角与天顶角

Sionna 路径方向使用方位角 $\phi$ 和天顶角 $\theta$：

$$
\mathbf u(\theta,\phi)=
\begin{bmatrix}
\sin\theta\cos\phi\\
\sin\theta\sin\phi\\
\cos\theta
\end{bmatrix}.
$$

天顶角 0° 指向 +Z，90° 位于水平面。不要把天顶角直接当成仰角。

### 10.4 分析范围

方位宽度、俯仰上下界和最大距离用于筛选已经求出的路径：

$$
m_l=\mathbb 1\left(
|\Delta\phi_l|\leq\Phi/2,
\eta_{min}\leq\eta_l\leq\eta_{max},
R_l\leq R_{max}
\right).
$$

这些参数不是天线方向图，也不会自动限制 Sionna 的全部候选射线。

## 11. Sionna RT 传播参数

### 11.1 传播机制

| 开关 | 含义 | 建议 |
|---|---|---|
| LoS | 无遮挡直达传播 | 检查准单站近零时延路径 |
| 镜面反射 | 几何光学表面反射 | 简单验证时首先开启 |
| 漫反射 | 粗糙表面散射 | 基线正确后再开启 |
| 绕射 | 边缘绕射 | 遮挡区研究时使用 |
| 折射/透射 | 穿透材料边界 | 必须确认材料参数有效 |

### 11.2 最大深度

最大深度限制路径允许的交互次数。深度从 1 增加到 2 后，候选路径组合和计算量可能显著增加。推荐逐级增加并比较新增路径是否有明确物理来源。

### 11.3 射线数量和随机种子

随机采样结果必须做收敛检查。至少比较两档射线数和两个随机种子，并记录：

- 主峰距离；
- 总路径能量；
- 强路径数量；
- MPC 未归一化 dB 数组的主要角度结构。

扇区候选射线是加速方式，可能漏掉初始方向在扇区外、经过反射后返回的路径。全空间采样应作为物理基线。

## 12. 阵列与波束形成

### 12.1 阵列导向矢量

阵元 $m$ 在方向 $(\theta,\phi)$ 上的相位响应为：

$$
a_m(\theta,\phi)=
\exp\left(j\frac{2\pi}{\lambda}\mathbf r_m^T\mathbf u(\theta,\phi)\right).
$$

常规导向权重为：

$$
\mathbf w(\theta_0,\phi_0)=
\frac{\mathbf a(\theta_0,\phi_0)}{\|\mathbf a(\theta_0,\phi_0)\|_2}.
$$

### 12.2 Tx 与 Rx 的区别

- Tx 物理方向图进入路径复系数计算；
- Rx 数字波束形成对已经保存的多阵元 CIR 做相干组合；
- 改变 Rx 数字权重不应改变路径几何；
- 改变 Tx 方向图需要重新运行仿真。

第 $l$ 条路径的相干合成结果为：

$$
z_l=\mathbf w_{Rx}^H\mathbf H_l\mathbf w_{Tx},
\qquad P_l=|z_l|^2.
$$

Tx 的“自定义阵元复权重”接受数字、`[re, im]` 或 `{"re": ..., "im": ...}`。预合成相控阵孔径采用行优先顺序；保留独立发送阵元通道的原生平面阵列采用列优先顺序。权重数量必须严格等于 `Tx 行数 × Tx 列数`，不能全部为零；系统在计算方向图前进行单位范数归一化。相控阵孔径模式会把这些权重直接嵌入 Sionna Tx 复场方向图，修改后必须重新运行仿真。

### 12.3 方向图预览检查

1. 主瓣峰值应位于设定导向角；
2. 增加阵列孔径后主瓣通常变窄；
3. Hann 加窗降低旁瓣但展宽主瓣；
4. 阵元间距明显大于 0.5λ 时需检查栅瓣。
5. Tx 和 Rx 预览分别显示在各自参数区域；自定义权重格式或数量错误时，预览会明确标记无效。

## 13. FMCW、距离-Doppler 与 CFAR

### 13.1 Chirp 和距离

线性调频斜率：

$$
S=\frac{B}{T_c}.
$$

静止目标拍频与距离近似满足：

$$
f_b\approx\frac{2SR}{c},
\qquad R\approx\frac{cf_b}{2S}.
$$

理论距离分辨率：

$$
\Delta R=\frac{c}{2B}.
$$

### 13.2 Doppler 和速度

$$
f_D=\frac{2v_r}{\lambda},
\qquad v_r=\frac{\lambda f_D}{2}.
$$

增加 chirp 数和相干观测时间可改善速度分辨率。静态建筑在理想模型中应集中在零速度附近。

### 13.3 热噪声

$$
P_n=kTBF,
\qquad F=10^{NF/10}.
$$

温度、有效噪声带宽和噪声系数共同决定噪声功率。

### 13.4 CA-CFAR

独立指数噪声假设下：

$$
\alpha=N\left(P_{fa}^{-1/N}-1\right),
\qquad T=\alpha\overline P_{train}.
$$

减小 $P_{fa}$ 会提高门限并减少虚警，同时可能漏掉弱目标。必须结合检测位置和门限图解释检测数量。

## 14. 三维路径与统计结果

### 14.1 路径长度与时延

$$
L_l=\sum_q\|\mathbf p_{q+1}-\mathbf p_q\|_2,
\qquad \tau_l=L_l/c.
$$

选择路径后，场景显示 Tx、所有交互点和 Rx 的完整折线。检查器同时给出时延、等效距离、AoA/AoD、能量、交互深度和对象。

### 14.2 距离角谱

距离-方位谱是路径功率在二维网格上的统计：

$$
P[r_i,\phi_j]=\sum_l P_l
\mathbb 1(R_l\in r_i)
\mathbb 1(\phi_l\in\phi_j).
$$

它不是波束扫描得到的超分辨率角谱，也不是 MPC 全景。

### 14.3 浏览器路径子集

原始结果可能包含数十万条路径。浏览器只加载主要路径用于交互，完整路径数量以归档统计为准。定量结论优先使用 `paths.csv` 和 NPZ 文件。

## 16. 常见问题与排查顺序

### 16.1 `Failed to fetch`

1. 访问 `http://127.0.0.1:8000/api/health`；
2. 检查浏览器 Network 面板中的请求 URL 和状态码；
3. 查看 `outputs/radar_workbench/logs/radar_api.log`；
4. 区分平台请求错误与浏览器扩展 `content_main.js` 错误。

### 16.2 三维场景空白

检查浏览器 WebGL 支持、GPU 驱动、控制台 Three.js 错误以及场景资源请求。路径数据存在不代表 WebGL 画布一定可用。

### 16.3 MPC 全红或全蓝

读取 `mpc_panorama.npz` 中未归一化 dB 数组的分布，检查归一化上下界。文件内该数组的字段名为 `raw_db`。单帧显示使用局部 40 dB 范围；跨位置训练应使用统一全局范围。

### 16.4 历史记录无法删除

确认当前集合是“我的仿真结果（可删除）”，而不是内置示例结果；再检查任务是否仍为真实运行状态。超过 24 小时的遗留队列状态不会继续阻止删除。

## 17. 打包、迁移与部署

## 18. 阵元因子、场景 JSON 与 CIR 噪声

### 18.1 发射与接收单元因子

“发射单元因子”和“接收阵元方向图”均可选择各向同性、3GPP 单元或自定义增益网格。自定义增益网格采用同一 JSON 格式：

```json
{
  "azimuth_deg": [-60, 0, 60],
  "elevation_deg": [-20, 0, 20],
  "gain_db": [
    [-35, -15, -35],
    [-18, 8, -18],
    [-35, -15, -35]
  ],
  "outside_gain_db": -60
}
```

`gain_db[i][j]` 对应第 `i` 个俯仰角采样和第 `j` 个方位角采样。两条角度轴必须严格递增、等间隔，至少包含两个采样点；最大尺寸为 361 个俯仰角点乘 721 个方位角点。网格内部采用双线性插值，网格外使用 `outside_gain_db`。当前格式描述共极化功率增益，不包含方向相关相位和交叉极化复电场。

两端最终方向图的定义为：

$$
G_{\mathrm{array}}(\phi,\theta)
=G_{\mathrm{element}}(\phi,\theta)
\left|A(\phi,\theta)\right|^2.
$$

前端在提交前执行与后端一致的尺寸、数值和等间隔校验；格式错误会显示具体原因并禁止运行。实验配置和运行快照分别保存 `element_gain_grid_json` 与 `gain_grid_json`，结果包中的对应文件为：

- `analysis/tx_element_pattern.npz`、`figures/tx_element_pattern.png`：发射单元因子；
- `analysis/tx_radiation_pattern.npz`、`figures/tx_radiation_pattern.png`：发射单元因子与阵列因子的合成结果；
- `analysis/rx_element_pattern.npz`、`figures/rx_element_pattern.png`：接收单元因子；
- `analysis/rx_steering_pattern.npz`、`figures/rx_steering_pattern.png`：接收单元因子与数字波束形成阵列因子的合成结果。

“自定义总增益（等效 1×1）”是为旧配置保留的另一种发射模式。它直接定义完整发射方向图并使用等效 1×1 辐射源，不再乘以多阵元阵列因子；界面和 `tx_radiation_pattern.npz` 的 `pattern_mode` 会明确标注这一语义。

编辑完成后，可使用参数面板底部的“保存参数”将单元因子、波束形成、传播求解和噪声开关写回当前实验方案。保存不会修改历史仿真结果；重新打开实验方案时会恢复完整网格和对应模式。

### 18.2 场景 JSON 导入导出

在右侧“场景几何”中可以导入或导出场景 JSON。JSON 包含地面、建筑位置、尺寸、三轴旋转角和材质。OBJ/PLY 模型导入仍使用“导入 3D 模型”按钮；场景 JSON 只保存模型引用和变换信息，不嵌入模型二进制文件。导入模型引用到另一实验方案时，应先在目标方案重新上传模型，再保存场景。

### 18.3 OpenStreetMap、GeoJSON 与混合场景

“导入 OSM / GeoJSON”支持 `.osm`/OSM XML、Overpass JSON 和 GeoJSON 建筑面。导入器读取建筑闭合面，将经纬度投影到以导入区域中心为原点的局部米制坐标，并根据 `height` 或 `building:levels` 生成建筑高度。没有高度标签时使用 12 m 的默认高度。每个对象会保留 OSM/GeoJSON 来源编号和源文件路径，便于回查。

导入方式有两种：

- “追加到当前场景（混合）”保留当前地面和建筑，把地图建筑加入同一方案；
- “替换当前建筑”用导入文件中的建筑替换当前建筑列表，地面仍可在编辑器中调整。

在“场景几何”中点击“在地图上框选”。拖动 OpenStreetMap 底图定位，滚轮或点击加减按钮缩放。点击“画矩形”后，沿街道拖出选区。演示时可以用“上海人民广场”定位。界面显示选区的宽高和经纬度，宽和高各限 5 km。选好“追加”或“替换”后点击“导入建筑”，再点击“保存场景”。保存后重新打开地图可看到本次查询范围。边缘建筑保留完整轮廓。追加 OSM 建筑时沿用已有地图坐标原点，已存在的 OSM 编号会跳过。

也可以展开“按坐标和半径获取”，输入中心经纬度和半径，半径上限为 5 km。在线底图需要浏览器访问 OpenStreetMap 瓦片，建筑查询需要 H100 服务器访问 Overpass。建筑查询地址通过 `RADAR_OVERPASS_URL` 配置。

导入后可以按名称或来源编号查找建筑，或直接点选三维预览中的建筑，调整位置、尺寸、旋转和材质。保存场景后生成新的场景 XML 修订。闭合建筑面的 `footprint_m` 直接挤出为多边形网格，原始面信息和 OSM 来源仍保存在对象中。OSM 关系型 multipolygon 的洞口暂不单独挤出。

### 18.4 CIR 复高斯白噪声

在“接收阵列与信号处理”区域开启“对 CIR 注入复高斯白噪声”，设置 `CIR 信噪比 dB` 和随机种子后重新运行。信噪比定义为有效 CIR 复数系数平均功率与复噪声平均功率之比。结果中：

- `cir.npz`：带噪 CIR；
- `cir_noiseless.npz`：同一随机传播结果的无噪声基准；
- `metrics.json` 和 `metadata.json`：记录目标SNR、实际SNR、信号功率和噪声功率。

该噪声作用于路径系数，不等同于对已采样 ADC 时域波形加噪声；若需要硬件接收机级噪声模型，应在 FMCW 时域采样之后单独建模。

发生仿真错误时，可按任务 ID 生成不包含大型 CIR 数值和模型文件的诊断包：

```bash
./scripts/collect_error_report.sh --job-id job_20260723_123456_xxxxxxxx
```

生成的 `deliverables/radar-error-report-<job_id>-<时间>.tar.gz` 包含任务配置、状态、完整 traceback、日志尾部、运行环境版本、关键源码哈希，以及 NPZ 数组的 shape/dtype 清单。将该压缩包连同界面操作说明一起提供即可复现和分析。

平台支持三种迁移范围：

| 范围 | 包含内容 | 推荐用途 |
|---|---|---|
| 最小代码包 | 代码、文档、已构建界面 | 在新机器建立空白平台 |
| 本地数据包 | 最小包、实验方案、本地仿真结果 | 继续当前工作 |
| 示例数据包 | 额外包含大型只读示例结果 | 离线演示或复核 |

推荐命令：

```bash
./scripts/package_radar_workbench.sh --with-local-data
```

目标机解压后运行：

```bash
./scripts/install_radar_workbench.sh
./scripts/verify_deployment.sh
./scripts/start_radar_workbench.sh
```

只浏览已有结果时使用 `./scripts/install_radar_workbench.sh --without-sionna`，无需 GPU，也不会安装 Sionna RT。完整的目标机要求、SSH 访问、磁盘目录、备份和升级步骤参见 `DEPLOYMENT_GUIDE.md`。
